## What Was Implemented
Google/Apple account linking now discards six provider-secret fields before writing D1. A new migration clears existing secrets, rebuilds the three auth tables with user-deletion cascades, removes orphan auth records explicitly, and adds a PKCE challenge column. A second migration adds shared fixed-window rate-limit counters.

All cookie-authenticated writes check their origin and media type before authentication or database access. D1 admits 60 account mutations per minute and 20 Coach calls per five-minute window per user; limits share state across separately loaded limiter modules. Account writes proceed with one message-only error log when the limiter fails; Coach returns a generic 503 without invoking the model. Plan/thread/message inserts enforce 25/100/500 quotas atomically and return exact 409 errors without orphan rows or timestamp changes.

Web profile users can open a Base UI alert dialog, cancel, or confirm permanent deletion. A ref prevents duplicate in-flight DELETE requests. Only a 204 clears athlete, plan, and Coach state and starts sign-out. Failed deletion shows a toast while retaining session and stores. Server deletion uses one batch and session validation confirms the users row exists, so a deleted user's old cookie fails on account and Coach APIs. Native deletion remains hidden pending phase 2 cookie/Bearer work.

Native login now creates a random verifier, keeps it in device-only secure storage across WebView reloads, and carries its S256 challenge through the hosted callback. Exchange reads/deletes the stored verifier, requires a matching hash, and burns wrong/missing-verifier attempts atomically. On each mint, at most 100 used or expired codes are purged; live codes remain. TTL is still 60 seconds. Native CORS is unchanged.

Next responses receive CSP, nosniff, referrer/permissions policies, and HSTS. Static export skips Next headers. public/_headers supplies the same policies for ASSETS; actual deployed ASSETS behavior still needs verification. CSP permits self-hosted inline bootstrap scripts, excludes unsafe-eval/external script hosts, and adds only accounts.google.com and appleid.apple.com to form-action to accommodate OAuth POST redirects. App source has no external avatar image loads; no image origin added. OAuth redirect compatibility remains manually unverified. Worker observability is enabled and server log sites avoid exception objects/request data. Non-force audit updates clear the production audit without new dependencies or major version bumps.
