## What Was Implemented
Fix round 1, limited to Troy's three-item /checkit queue. Existing client, drawer, page, API request construction, server files, and dependency versions were preserved.

Retry now locates the last user message and removes only that turn and its trailing response before re-sending it with the same saved local ID. A reopened history shaped [user, assistant, user] retains the earlier assistant reply, its complete history, and its saved user ID. The companion [user, assistant, user, failed assistant] test also passes. Retry still saves only the new assistant reply, never the already-saved user again.

If an athlete sends before openThread or last-thread restoration finishes, that prompt starts its own new chat immediately. The pending history selection is invalidated, its device pointer cleared, and a fresh conversation queue owns the visible prompt and reply. Streaming remains immediate. The new thread ID matches the visible turns; neither a late history response nor a save into the unopened thread can create a hidden continuation. If history finishes first, normal continuation behavior remains unchanged. This chooses a fresh chat over waiting for history because the handoff requires chatting not to be blocked by storage loads.
