## Original Goal

Add real Auth.js Apple/Google authentication backed by Cloudflare D1, a server request gate, sign-in and sign-out controls, tested Apple JWT signing, and a native authentication shape. Preserve the existing local training stores and static iOS export. Real OAuth credentials, a remote database, and a hosted origin are explicitly deferred.

## What Was Implemented

Visitors now see Apple and Google buttons on a public sign-in page. Protected web routes redirect to that page before rendering app content, preserving the requested destination. Auth.js validates encrypted JWT sessions without a database query in the proxy. Authentication handlers lazily resolve D1 and configure the two real providers from environment variables. Successful provider sign-in is designed to persist users/accounts through the official adapter; no successful OAuth or persistence claim is made without credentials.

Sessions use `strategy: "jwt"` and a 30-day maxAge in src/auth.ts. The adapter's sessions table exists but is unused by this strategy. Cookie security settings remain Auth.js defaults. The callback exposes the user ID. Apple client secrets are signed with ES256 and runtime-provided keys; tests verify the signature, issuer, subject, audience, key ID and 180-day expiration. No Apple email filter or custom account-linking behavior was added.

The profile includes Sign out; the desktop landing Sign In points to /sign-in. The static exporter excludes the proxy and API, preserving the existing native entry redirect. The app URL scheme and one Capacitor plugin are registered. A supporting native gate refuses app content without a hosted session. Native sign-in opens the external origin through Capacitor's existing top-level navigation handling; deep links are never accepted as authentication proof. Native cookie exchange/completion remains designed, not implemented or verified, under the explicit DEPLOY_DEFERRED allowance.

Dependencies and justification:
- next-auth 5.0.0-beta.32: requested provider/session server and client APIs.
- @auth/d1-adapter 1.11.3: requested D1 user/account persistence.
- @opennextjs/cloudflare 1.17.1: requested lazy runtime bindings and local development initialization. Pinned because latest 1.20.6 rejects Next 16.1.6; 1.17.1 declares compatibility. No legacy peer override used.
- @capacitor/app 8.1.1: requested appUrlOpen listener, the only added native plugin.
- jose 6.2.12: direct declaration for Apple ES256 JWT creation and signature verification, explicitly permitted by the handoff.
- wrangler 4.136.2: local D1 migrations/bindings and future remote migration command.
- vitest 3.2.7: unit tests; latest 5.0.1 rejects the existing Node 20 type declarations, so compatible major 3 is used.

The migration copies the installed adapter's four CREATE TABLE statements. The installed adapter lacks a provider/providerAccountId unique constraint despite the handoff's claim; the migration adds the specifically requested unique index. D1 additionally creates its own migration/metadata tables; the application migration creates only the four auth tables.
