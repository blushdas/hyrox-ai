## Original Goal
Save Coach AI conversations through the account-scoped thread API; restore the last thread, reopen conversations through History, and start empty chats without creating empty saved threads. Preserve the current streaming request and all existing Coach behavior. Do not import the unmerged core-schema implementation.

## What Was Implemented
A typed client checks all four API response shapes and returns explicit success, unauthorized, missing-thread, or failure results, including transport and malformed JSON failures. It validates nested citations and web sources and keeps the server's message IDs separate from new local message IDs.

Each conversation owns an ordered save queue. The first prompt creates a thread with its trimmed first 60 characters, then saves the user turn. Streaming begins immediately and never waits for that queue. Completed assistant replies and nonempty stopped partial replies save once; error and empty assistant turns do not save. Retry preserves the local user ID so its user save is not repeated, including when the original save is still pending. A Stop during terminal reader cleanup also saves the completed reply. Delayed persistence cannot assign its old thread ID to a newly opened chat.

History uses the existing native Sheet dialog with its label, Escape behavior, focus restoration, and shared reduced-motion styles. Threads are sorted newest first and show title and relative time, with loading, empty, error, and quiet signed-out states. Selecting a thread stops the old stream, restores messages without changing citations or web sources, and closes the panel. New chat clears messages, thread identity, and the device's last-thread pointer while keeping saved threads. The Coach page restores the last-thread pointer once per mount, retains its existing session key, and places one save notice above the composer.

Save/load failures leave Coach usable. Unauthorized storage calls suppress the notice. Device storage access is optional and guarded. The API request construction remains byte-identical to origin/main; no server route, database helper, API helper, migration, dependency, or environment file changed.
