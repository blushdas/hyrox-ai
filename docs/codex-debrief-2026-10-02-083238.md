## Original Goal
Make Coach AI replies appear steadily through bursty arrivals, block finalization and reply completion. Preserve existing controls and accessibility while changing only the client render layer.

## What Was Implemented
Text now reveals through a fractional character accumulator at a slowly adapting rate (100 to 240 characters/second, two-second smoothing window), capped at eight characters per animation frame. Short leftovers drain at the same rate after the server finishes. Previously complete messages mount fully visible. Reduced motion returns received text directly without a reveal loop, and each keyed message owns fresh pacing state.

The live tail now uses the same Markdown block renderer, prose width, spacing, headings, lists and inline styles as finalized text. Its zero-width positioned cursor does not contribute to wrapping. A completed advice reply waits until all received text has revealed before replacing it with an opacity-only Take-card fade using the existing motion transition.

User and assistant messages are memoized. The thread passes a stable retry callback that calls the latest parent callback, preserving current retry context without per-chunk callback invalidation. Bottom following uses one resize-triggered, coalesced animation loop, caches the destination and moves forward toward it. Upward wheel, keyboard and touch input pauses pending follow frames. Latest remains available when scrolled above the bottom, including after the network stream ends while text drains.

These are implemented changes, not verified claims of visual smoothness: the real authenticated flow could not be reached. The five Current State diagnoses were confirmed in the original source only; none was profiled in the browser. All existing thinking, error, citation and message-action components remain in place.
