## Original Goal

A user who finished or skipped onboarding must never be sent back to onboarding, on any device, after sign-out, or after clearing storage. New users get a Skip control, and the race date uses a proper in-app date picker. The account-sync layer already exists on this branch (rebased on current main, force-pushed): extend it rather than rebuilding it.

## What Was Implemented

Completed and skipped accounts retain their onboarding completion even without a training plan. The app guard now uses that completion flag, and the onboarding page waits for account sync before displaying its first step or redirecting a completed account. Skip appears on all five steps, deduplicates repeated taps, saves completion to the signed-in account, and then opens the dashboard. Empty dashboards offer Build my plan. That control and Profile redo explicitly open onboarding on demand. A skipped Profile page also keeps sign-out and deletion controls available.

Skip stores an explicit marker alongside the completion timestamp. Reads expose no fabricated athlete profile, repeated skips preserve the original timestamp, and skipping never overwrites a real profile. Finishing later clears the marker through the existing profile save. Owned local profiles and plans can backfill an empty account once per tab session; overlapping hydration runs share that upload. Conditional SQL writes plus If-None-Match/HTTP 412 protect profiles created concurrently. Foreign and unowned data remain excluded.

Both race-date fields now use one calendar built on installed Base UI popover primitives. Its grid supports arrow keys, Enter, Escape, month controls, visible focus, disabled past days, and 44px targets. Motion follows existing tokens and reduced-motion settings. Calendar-day comparison accepts exactly four weeks despite local time or daylight-saving boundaries.

Deviations & Judgment:
- inference | Required profile columns cannot represent an absent profile directly. Add a single checked marker column and private valid filler values rather than rebuild the table or add a separate table. No persistent/live database migration was applied.
- inference | Backfill uses an optional standard conditional header and HTTP 412; existing profile JSON remains unchanged except the authorized Skip request. This closes the concurrent-profile overwrite window.
- inference | An intentional redo preserves the current plan until the user finishes. Clearing it immediately would leave completed accounts without their plan if they cancel or Skip.
- correction | The historical migration test copies current fixture rows into an older schema; exclude the later marker column from that copy. Vitest includes only .test.ts, so the new component test uses that extension.
- inference | Browser checks use an explicitly labelled local component fixture, as permitted by the handoff. Authentication was not forged; signed-in criteria remain Partial.
- inference | Existing athlete-store completion/owner setters suffice; no athlete-store edit needed.
