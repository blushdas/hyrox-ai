## Done When
- `/sign-in` renders the two provider buttons (exact copy above), no email/password inputs, and shows a visible error line when `?error=` is present.
- `src/auth.ts` configures Google + Apple from env, uses the D1 adapter, JWT session strategy (>= 30 days), and `src/app/api/auth/[...nextauth]/route.ts` exposes the handlers; `curl /api/auth/providers` lists `apple` and `google`.
- `wrangler.jsonc` has one D1 binding `DB` -> `finisher-db` (placeholder id, no secrets) and `npx wrangler d1 migrations apply finisher-db --local` creates `users`, `accounts`, `sessions`, `verification_tokens` and nothing else.
- `src/proxy.ts` redirects every unauthenticated request to a protected route to `/sign-in?callbackUrl=<path>` (307/302) server-side, treats a garbage session cookie as unauthenticated (no 500), leaves `/`, `/api/waitlist`, `/api/auth/*` public, and sends a signed-in user on `/sign-in` to `/dashboard`.
- `/profile` has a `Sign out` button that calls Auth.js sign-out and lands on `/sign-in`.
- Landing header "Sign In" links to `/sign-in`; `e2e/navigation.spec.ts` updated only for that expectation; `e2e/landing.spec.ts` and `e2e/onboarding.spec.ts` pass unchanged.
- `npx vitest run` passes with tests for the Apple client-secret builder (claims/header/alg/expiry) and the protected-route matcher; both fail if the logic changes.
- `.env.example` documents every env key with placeholders; `.gitignore` covers `.dev.vars`, `.wrangler/`, `*.p8`; no secret material tracked.
- `scripts/build-ios.ts` excludes `src/proxy.ts`; `ios/App/App/Info.plist` registers the `finisher` URL scheme; `npm run build:ios` and `npx cap sync ios` exit 0; native sign-in shape uses `NEXT_PUBLIC_AUTH_ORIGIN` and at most one Capacitor plugin.
