## Original Goal
Make FINISHER feel alive like a native iOS app. Add a one-time cold-start splash, tactile press feedback, staggered list entrances, spring-timed route/sheet/skeleton transitions and a ProMotion plist key, by extending the existing motion system (tokens in `src/app/globals.css`, helpers in `src/lib/motion.ts`, framer-motion ^12.35.2). Upgrade what exists; do not rebuild it. Animate transform and opacity only.

## What Was Implemented
FINISHER now opens with a centered green wordmark on the launch background. It dips, expands through its letterforms and reveals the already-mounted application over 900ms. A module-level gate limits it to one play per document lifetime, including client redirects. The overlay ignores pointer input and never controls whether auth or route children render.

Buttons and links compress to 97% on press and settle with the shared snappy spring. Existing route and tab-indicator animations use physical springs. Workout, plan and exercise lists gain bounded entrances. The sheet keeps native dialog behavior and its backdrop while moving over 500ms. When a loading skeleton unmounts on the same route, an inert, accessibility-hidden visual copy fades out for 150ms; its replacement enters over 210ms after that delay.

Reduced-motion CSS substitutes opacity fades and suppresses press, route, row, sheet and splash movement. Loader labels use CSS media variants so the server and client render identical markup. The iOS plist opts into the system's higher refresh rate behavior. Neither locked chat file nor expo-shell changed. The optional chat-bubble change remains Partial because global CSS cannot distinguish new messages from history with the existing locked renderer.

Deviations & Judgment:

- inference | Suspense removes fallback DOM immediately, so CSS alone cannot show an unmount exit. A 150ms inert visual snapshot supplies that exit without delaying content or changing data. Strict Mode replay and cross-route exits are skipped.

- correction | Browser QA exposed reduced-motion hydration differences in route transforms and loader labels. First route markup is now invariant; preference-specific labels use CSS. Final normal/reduced fixture checks captured console errors and page errors and found no hydration errors.
